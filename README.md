# proxy-qr — живые серверы + QR-код для телефона

Сервис берёт публичные подписки (vless / vmess / trojan), **реально проверяет** каждую
ноду трафиком через ядро Xray и публикует мобильную страницу: у каждого рабочего сервера
есть кнопка «QR-код» и «Копировать». Ничего не нужно арендовать — проверку и страницу
делает GitHub Actions + GitHub Pages, бесплатно.

```
подписки (URL) ──► разбор ссылок ──► TCP-фильтр ──► реальный запрос через Xray
                                                      │
                        работает только то, что прошло ─┐
                                                       ▼
                         dist/<slug>/index.html  +  qr/*.svg  +  sub.txt
                                                       │
                                              git push в gh-pages
                                                       ▼
                              https://<user>.github.io/<repo>/<slug>/
```

## Почему «проверено» — это правда

Мёртвые ноды в бесплатных подписках выглядят живыми: TCP-порт открыт, а UUID отозван.
Поэтому проверка двухступенчатая:

1. **TCP-connect** (3 с) — дешёвый отсев мёртвых адресов (обычно отсеивается ~40–50 %).
2. **Реальный запрос** через каждую ноду: ядро Xray поднимает N socks-портов, `curl`
   тянет `generate_204` через каждый. В список попадает только сервер, через который
   трафик реально прошёл. Замеряется TTFB — он же «пинг» в карточке.
3. Дополнительно у топ-6 замеряется скорость скачивания (если включено).

`state.json` хранит историю: карточка с зелёной плашкой «96 % аптайм» работала почти в
каждой из последних проверок, «новый» — встретилась впервые.

### Обновление без GitHub Actions (уже работает)

`refresh_hidden.vbs` запускает `refresh.bat` без окна консоли; значения (токен, адреса,
путь к `xray.exe`) берутся из `.env.local` в корне проекта — он в `.gitignore`.
Пересоздать задачу:

```cmd
schtasks /Create /TN "proxy-qr refresh" /SC MINUTE /MO 20 ^
  /TR "wscript.exe \"D:\Software\proxy-qr\refresh_hidden.vbs\"" /F
```

Плюс этого пути: ноды проверяются **с российского IP**, то есть ровно так, как их увидит
телефон. Минус: пока ПК выключен, страница показывает последние результаты (в шапке
видно «обновлено N ч назад»).

### Если нужен облачный крон (работает при выключенном ПК)

Файл workflow лежит в `ci/refresh.workflow.yml`, но залить его автоматически не дал
токен: у OAuth-токена нет scope `workflow` (GitHub отказывает в записи
`.github/workflows/*`). Добавляется один раз вручную, 30 секунд:

1. В репозитории: **Add file → Create new file**, имя `.github/workflows/refresh.yml`.
2. Скопировать туда содержимое `ci/refresh.workflow.yml`, **Commit**.
3. **Actions → refresh → Run workflow**.

После этого проверка и публикация идут с GitHub каждые 20 минут независимо от ПК.
Секрет `SITE_SLUG` и права Actions (`Read and write`) уже настроены.

## Быстрый старт с нуля (другой аккаунт)

1. Создайте **публичный** репозиторий (Actions и Pages для публичных репозиториев
   бесплатны; приватность даёт неугадываемый `slug`, а не приватность репозитория).
2. Загрузите в него эти файлы (`qrservice/`, `config.json`, `requirements.txt`,
   `ci/refresh.workflow.yml` → `.github/workflows/refresh.yml`).
3. **Settings → Actions → General → Workflow permissions** → `Read and write permissions`.
4. **Settings → Secrets and variables → Actions → New repository secret**:
   `SITE_SLUG` = любая случайная строка, например `k7f2m9x4q1` — это адрес страницы.
5. **Settings → Pages → Source**: `Deploy from a branch`, ветка `gh-pages`, папка `/ (root)`.
6. **Actions → refresh → Run workflow** (первый запуск вручную; дальше — каждые 20 минут).

Готово: `https://<ваш-логин>.github.io/<репозиторий>/<SITE_SLUG>/`

Внутри страницы есть блок «Подписка»: ссылка `…/sub.txt` — её достаточно один раз
вставить в v2rayNG («Подписки → ＋»), и клиент будет сам подтягивать свежий список.
QR-коды отдельных серверов — для разового подключения.

## Где это живёт: варианты хостинга

| Вариант | Цена | Карта | Доступность из РФ | «Всегда онлайн» |
|---|---|---|---|---|
| **GitHub Actions + Pages** (по умолчанию) | 0 | не нужна | обычно да, но GitHub в РФ периодически троттлится | да (cron 20 мин, бывает задержка 5–15 мин) |
| Свой ПК + локальный сервер (`--serve`) | 0 | не нужна | 100 % в своей Wi-Fi, без интернета | только пока включён ПК |
| Свой ПК + публикация на любой статик-хостинг | 0 | зависит | зависит от хостинга | пока ПК включён |
| Yandex Object Storage (статик-хостинг) | в бесплатном гранте | нужна | 100 % | да, но заливку надо запускать самостоятельно |

Главная оговорка честно: **GitHub в России иногда замедляют и частично фильтруют**.
Если `github.io` у вас не открывается — тот же `dist/` можно залить на любой хостинг
статики (`run.py` пишет обычные файлы), либо поднять страницу на своём ПК.
Тест нод при этом идёт **из зарубежного дата-центра GitHub**, а не из России: сервер,
рабочий оттуда, у вашего оператора может быть закрыт. Для точности запускайте
`run.py` локально (тогда в шапке страницы будет «Проверено локально»).

## Локальный запуск на Windows

```bash
cd D:/Software/proxy-qr
uv venv --python 3.12 .venv
uv pip install --python .venv/Scripts/python.exe segno
# ядро: положите xray.exe в bin/ или укажите XRAY_BIN (подойдёт из v2rayN)
XRAY_BIN="D:/Software/v2rayN/v2rayN-windows-64/bin/xray/xray.exe" \
SITE_SLUG=demo PAGES_URL="http://192.168.1.10:8099" \
.venv/Scripts/python.exe -m qrservice.run --serve 8099
```

Открыть с телефона в той же Wi-Fi: `http://192.168.1.10:8099/demo/` — QR-коды уже
абсолютные, сканируются нормально. Флаг `--serve` держит страницу, `--limit 40`
проверяет только первые 40 нод (быстрая отладка), `--no-speed` без замера скорости.

Публикация на GitHub из локального запуска: в `.env`/окружении `GITHUB_TOKEN`,
`PUBLISH_REPO=user/repo`, `PUBLISH=1`.

`PUBLISH_REPO` принимает и полный URL remote (`https://git.example.com/site.git`), и
локальный путь (`D:/backup/site.git`) — так можно держать зеркало на диске или на своём
git-сервере. Проверено: 56 файлов уезжают в ветку, повторный пуш идемпотентен.

## Настройки (`config.json`)

| Ключ | Смысл |
|---|---|
| `subscriptions[].url/name/enabled` | источники конфигов (base64 или обычный список ссылок) |
| `fetch.timeout/attempts/max_per_sub` | как качать подписки |
| `probe.kinds` | какие протоколы проверять (в Xray 26 нет `ss` — Shadowsocks удалён) |
| `probe.tcp_timeout/tcp_workers` | TCP-предфильтр |
| `probe.batch/lanes/workers` | сколько нод в одном процессе ядра и сколько полос параллельно |
| `probe.ping_urls/ping_timeout` | чем проверять (по умолчанию gstatic + cloudflare 204) |
| `probe.speed_top/speed_url` | замер скорости у топа (`0` — выключить) |
| `site.title/slug/max_nodes` | заголовок, адрес страницы, сколько серверов показывать |
| `site.refresh_seconds` | авто-перезагрузка страницы в браузере |
| `publish.repo/branch/pages_url` | куда публиковать (в Actions задаётся через env) |

`slug` лучше держать в секрете `SITE_SLUG`: страница не индексируется (`noindex`), но
по прямой ссылке её увидит любой, кому вы её передадите.

## Клиенты

- **Android**: v2rayNG, Hiddify, NekoBox — «＋» → «Сканировать QR-код» или «Импорт из
  буфера обмена». Подписка: «Подписки» → «＋» → URL `…/sub.txt`.
- **iOS**: Streisand, Shadowrocket, V2Box — сканер QR встроен.
- **Windows/ПК**: v2rayN, Hiddify — «Импорт из буфера обмена».

## Если что-то не работает

- **0 рабочих серверов** — подписки опустели или все ноды отозваны. Проверьте лог
  Actions: там по каждой подписке написано, сколько ссылок пришло.
- **`unknown config id: ss`** — нода Shadowsocks; в Xray 26 протокол удалён, такие ноды
  отфильтрованы в `probe.kinds`. Для SS нужен sing-box, это другой движок.
- **404 на странице** — не включён Pages (шаг 5) или не отработал первый workflow.
- **`publish` падает с 403** — в Settings → Actions не выданы права `Read and write`.
- **Батч не поднимается** — один битый конфиг валит весь батч; код автоматически делит
  батч пополам и изолирует такой узел (в логе — «конфиг отвергнут ядром»).
- **Cron не запускается через 60 дней** — GitHub отключает расписание у «спящих»
  репозиториев; достаточно раз в пару месяцев нажать Run workflow.

## Состав

```
qrservice/nodes.py    разбор vless/vmess/trojan/ss, дедупликация
qrservice/xraycfg.py  конфиги ядра (outbound ноды, батч на N socks-портов)
qrservice/core.py     запуск Xray, ожидание портов
qrservice/subs.py     загрузка подписок, TCP-предфильтр
qrservice/probe.py    реальные замеры через ядро, скорость
qrservice/site.py     мобильная страница, QR-SVG, sub.txt, state.json
qrservice/publish.py  git push в ветку gh-pages
qrservice/run.py      оркестрация + локальный сервер
tests/smoke.py        проверки разбора и сборки страницы (без сети и ядра)
```
